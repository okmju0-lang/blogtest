## 3줄 요약

1. AWS는 MCP가 Linux Foundation으로 옮겨가며 장기 성공 가능성과 중립성이 더 커졌고, 이제 에이전트 아키텍처의 표준 구성 요소가 됐다고 평가한다.
2. AWS는 다수의 MCP 서버를 만들고 코드 어시스턴트와 Bedrock AgentCore에 MCP를 통합했으며, 자체적으로 Tasks·Elicitations·structured tool output 같은 사양 확장에도 기여했다.
3. AWS Knowledge MCP 서버의 GA, 신규 AWS MCP Server 프리뷰, 원격 MCP 지원은 MCP가 로컬 실험에서 운영 환경으로 이동하고 있음을 보여준다.

## 핵심 인사이트

1. **중요해진 이유는 운영 기능의 추가**: Tasks와 Elicitations 같은 기능은 MCP를 단순 연결 규격에서 장기 실행 워크플로우 규격으로 확장한다.
2. **원격·서버리스 지원이 핵심 전환점**: MCP가 데스크톱 실험을 넘어 기업 인프라 안에서 배포 가능한 구조로 이동하고 있다.
3. **벤더 중립성과 실사용이 동시에 강화**: AWS가 “all-in on MCP”라고 말하는 배경에는 개방형 거버넌스와 고객 수요가 동시에 있다.

## AX 관련성

- **태그**: 기술트렌드, 운영자동화, 인프라
- **관련성 설명**: 기업이 MCP를 검토할 때 단순 연결 기능이 아니라 비동기 처리, 인간 개입, 원격 배포까지 포함한 운영성을 봐야 함을 보여준다.
